# Video visual assets — build, don't hunt

We make explainer videos for a **technical** audience. The visuals must be as
precise as the script. A generic stock screenshot almost never says the exact
thing the narration says — so **we build the visual ourselves**. HTML, SVG,
CSS, artifacts, generative code, real UI mockups: this is our home turf. Use it.

> **JP's founding principle (2026-08-18):** "We are tech, and most of the stuff
> we need to display we can create it. We don't need an image *showing* a thing
> when we can *build* the thing itself — the real way it's specified." When a
> beat needs "an example of X", the default is to **construct a correct,
> believable X**, not to google a picture of one.

## The decision: build vs screenshot vs generate

For every visual beat, pick the cheapest technique that is still *precise and
credible*. In rough priority:

| Technique | When it's right | Example |
|-----------|-----------------|---------|
| **Build HTML mockup** (default) | You need to show a UI, a document, a form, a table, a label, a flow — anything that is "an example of how X should look". You control every word. | Consent gate, audit-log table, an Article-50-compliant AI disclosure. |
| **Real web screenshot** | Authenticity is the *whole point*: the actual law, a real standard's real page, a real product's real UI that the viewer would recognize. Only when the real thing genuinely exists and reads clearly. | EUR-Lex / AI-Act-Explorer Article 50 text (it IS the law). |
| **Generative SVG/CSS** | You need an "image" (art, portrait, texture, chart) and want zero copyright/download and full control. | An AI-generated-looking artwork to then label. |
| **MDGraph diagram** | A flow / relationship / architecture. Use `scripts/generate-diagram.ts` (pre-rendered SVG, Remotion drives the reveal). | Compliance flow. |
| **Artifact (claude.ai)** | A richer interactive/visual page worth sharing or iterating with JP before baking into the video. | Design explorations. |
| **html → PDF → image** | You specifically want a "document/paper/report" look. | A faux one-pager, a certificate. |

**Anti-pattern (learned the hard way):** screenshotting a company's *marketing
homepage* to stand in for "an example of their feature". The homepage rarely
shows the feature doing the thing. `contentcredentials.org` does NOT show an
"AI-generated content label" — it's a hero page. We rebuilt the label ourselves.
If the screenshot doesn't literally show the claimed thing, **build it.**

## Build it the way it's REALLY specified (domain accuracy)

When we build "an example of X", X must be *correct*. We did the research — use
it. Don't hand-wave a plausible-looking box; render the thing the way the spec /
law / standard actually requires. This is our credibility with a technical
audience.

### Worked example — EU AI Act Article 50 disclosure (the SGI video)

An "AI-generated content label" done *correctly* per Article 50 has three parts:

- **Art. 50(2) — machine-readable + detectable.** Provider outputs (synthetic
  audio/image/video/text) must be "marked in a machine-readable format and
  detectable as artificially generated or manipulated." → show a **C2PA /
  Content Credentials** style provenance manifest (the "cr" pin, issuer,
  signature), not just a sticker.
- **Art. 50(4) — deployer disclosure (deep fakes).** Content that is an AI
  deep fake must be **disclosed** as artificially generated/manipulated. → a
  **visible** "AI-generated" badge on the asset.
- **Art. 50(5) — clear and distinguishable.** The info must be provided "in a
  clear and distinguishable manner at the latest at the time of the first
  interaction or exposure." → the visible badge must be legible and not hidden.

So a *correct* AI-label mockup = the image + a visible "AI-GENERATED" badge +
a machine-readable provenance panel (C2PA) + a line citing Art. 50. That's what
a technical viewer respects. A random watermark screenshot is not that.

> Keep a short, sourced spec block like the above for whatever domain the
> current video covers. Capture it while researching, reuse it while building.

## The reproducible pipeline (don't hand-screenshot)

Assets are generated by a script driven by a per-video manifest, so they can be
regenerated and version-controlled. Never leave a "I manually screenshotted this
once" asset — wire it into the manifest.

- **Script:** `scripts/generate-images.ts` — `npx tsx scripts/generate-images.ts <slug> [out1.jpg ...]`
- **Manifest:** `content/<slug>/images/sources.json` — array of `jobs`, each:
  - `type: "url"` → screenshot a live page. Fields: `url`, `viewport`, `hide[]`
    (CSS selectors of banners), `waitFor` (ms or selector), `scrollTo` +
    `scrollOffset`, `selector` (element shot), `clip` (crop rect).
  - `type: "html"` → screenshot a local mockup. Fields: `html` (path under
    `content/<slug>/images/`, mockups live in `mockups/`), `viewport`.
  - Common: `out` (filename under `public/<slug>/images/`).
- Output lands exactly where `src/lib/ImageBeats.tsx` reads it. A missing file
  degrades to "beat renders nothing" — never breaks the render.

### Mockup cohesion (Terminal style)

Mockups that are meant to feel *inside* our world use the Terminal palette so
they blend; assets that are meant to read as an *external citation* can stay in
their native (often light) look — the green border + label frames them as a
quote. Both are valid; choose deliberately.

- Palette: `--green #39FF88`, `--cyan #4DE8FF`, `--bg #04070A`, red `#FF5C5C`.
- Font: **JetBrains Mono** (matches the video). Link Google Fonts, wait
  `document.fonts.ready`, fall back to `ui-monospace`.
- Render landscape ~1280×720 (or taller then `clip`), `deviceScaleFactor: 2`.

### Asset aspect ratio — author TALL (rule, 2026-08-18)

Our frame is vertical (1080×1920) and the layout gives the image the **bottom
half** (~960px tall). Landscape assets (16:9 / ~1.5) only reach ~560-660px tall
at full width, leaving dead space. **When you author a NEW mockup or capture,
make it ~4:3 or taller** (e.g. viewport 1000×820, or capture a taller crop) so
it fills the bottom half. Existing SGI assets are landscape and grandfathered —
don't regenerate them just for this, but every future one should be tall.

### A step section that DOES something — the accumulating code block

Dead air is the enemy. In the SGI Terminal, the steps section (~25s+) used to be
a static faint icon. Now it's a **`comply.py` code editor panel that types a
"compliance function" line-by-line, one call appended per real step** (JP's idea,
2026-08-18). The concept: a funny function name (`avoid_big_fat_fine()`) whose
body is invented pseudo-code — one believable call per step, typed letter-by-
letter with syntax highlighting, cursor blinking, cumulative across steps. We
invent the names, never real bodies. This is the pattern for any "N steps /
checklist / build-this" section: **turn the list into an artifact that assembles
itself on screen.** See `CodeBlock` / `CodeLineView` in `Terminal.tsx`.

### Enumerations → word-synced icons (JP, 2026-08-18)

**When the narration lists things, put an icon on each thing, on the word.**
"…writes copy, generates images, or creates any content…" → a document icon pops
in on "copy", an image icon on "images", audio + video icons on "content". They
build into a **centered row above the caption**, then fade out together when the
list ends. It turns a flat sentence into something that reads instantly.

- Component: `src/lib/WordIcons.tsx` — takes `cues: {atMs, icons[]}[]`, `toMs`,
  `color`, `top`. Icons pop in (spring) at their `atMs`, persist, fade at `toMs`.
- Icons are **inlined Lucide paths** (lucide.dev, ISC) in a `LUCIDE` map — no
  runtime dependency. Add an icon by pasting its inner SVG. (lucide-react is the
  alternative if you'd rather depend on it.)
- **Sync from the captions, not hardcoded ms** — resolve each cue's `atMs` by
  finding the word in `captions` (`captions.find(c => /copy/i.test(c.text))`),
  so it survives a voice/script change like everything else.
- **Placement:** centered, above the caption. Check what else occupies that band
  at that moment (in the SGI hook the diagram is there but nearly empty during
  the enumeration, so the row sits cleanly). Default `top` ~420 with a ~108px
  icon works above a caption anchored at 660.
- This is a general pattern: any list (features, formats, steps, risks) becomes a
  row of icons appearing on-beat. Reach for it whenever the script enumerates.

### Sizing on screen (ImageBeats)

`ImageBeat` supports per-beat `width` (default 640) and `bottom` (default 150).
**Hero beats get to be big and readable** — the Article 50 card is on screen
~20s and IS the subject, so it renders at `width: 940`. Don't leave the hero as
a thumbnail when there's empty screen. Border/glow/label scale with `width`.
Watch the centered caption band (~vertical middle) — keep the card's top below
it (a 940-wide card at `bottom: 110` clears a 2-line caption).

## Gotchas (Puppeteer capture)

- **Cookie/consent banners inject async** — hide them AFTER `waitFor`/`scrollTo`,
  not before. The script also nukes any `position: fixed/sticky` element whose
  text matches /consent|cookie|gdpr/. We **never** click "Accept".
- **Don't over-crop by shrinking the viewport** — lazy-loaded content (galleries)
  may not render at a short viewport. Load tall, then `clip` the crop.
- `deviceScaleFactor: 2` for crisp text; JPEG quality ~92.
- Absolute paths when spawning external procs (see whisper.cpp note in `_STATE`).

## Voice & character direction (Fish Audio)

The narration voice is a **character** (currently Borat via Fish, voice id
`403c9c73…`, on the free `s2.1-pro-free` endpoint). What makes a character
alive is *expression* — so **write the script with Fish audio tags throughout**,
not as flat text. Tags go inline in the `text` field (no separate param); on
S2/S2.1-pro they use **square brackets** and can even be **free-form natural
language** ("[sarcastic, leaning in]"), not just the fixed set. (Legacy S1 uses
parentheses.) Put an emotion/tone tag at the start of most sentences and shift it
as the mood shifts — a dictator-of-Wadiya bit laughing at the law wants
`[sarcastic]`, `[mocking]`, `[laughing]`, `[shouting]` sprinkled in.

**Full supported tag set (Fish docs, 2026-08):**

- Emotions (basic): `[happy] [sad] [angry] [excited] [calm] [nervous] [confident]
  [surprised] [satisfied] [delighted] [scared] [worried] [upset] [frustrated]
  [depressed] [empathetic] [embarrassed] [disgusted] [moved] [proud] [relaxed]
  [grateful] [curious] [sarcastic]`
- Emotions (advanced): `[disdainful] [unhappy] [anxious] [hysterical]
  [indifferent] [uncertain] [doubtful] [confused] [disappointed] [regretful]
  [guilty] [ashamed] [jealous] [envious] [hopeful] [optimistic] [pessimistic]
  [nostalgic] [lonely] [bored] [contemptuous] [sympathetic] [compassionate]
  [determined] [resigned]`
- Tone / delivery: `[in a hurry tone] [shouting] [screaming] [whispering]
  [soft tone] [emphasis]`
- Non-verbal sounds: `[laughing] [chuckling] [sobbing] [crying loudly] [sighing]
  [groaning] [panting] [gasping] [yawning] [snoring] [clear throat]`
- Crowd / timing: `[audience laughing] [background laughter] [crowd laughing]
  [break] [long-break]`
- Free-form (S2.1-pro): any natural-language cue in brackets, e.g.
  `[muttering under breath]`, `[building to a shout]`.

### The cached expression bank (drop-ins, no Fish call)

Short character interjections — "Aha!", "Hmm", "No no no", laughs, sighs, "Great
success!", etc. — are pre-generated and **cached** so we can drop one onto a beat
WITHOUT hitting Fish again ("here goes an *Aha!*").

- Source list: `content/voice/expressions.json` ({id, text}; text leads with a tag).
- Generator: `npx tsx scripts/generate-expressions.ts` (one Fish call PER
  expression — a single blob split by silence mis-aligns because interjections
  have internal pauses; per-call is free on s2.1-pro and perfectly clean). Pass
  ids to re-roll a bad take: `... generate-expressions.ts gasp` (Fish sometimes
  emits a dud — the script has an id filter for exactly this).
- Output: one `public/brand/voice/<id>.mp3` per clip + `manifest.json`
  ({id, text, tag, file, durationMs}).
- To USE one in a video: `<Audio src={staticFile("brand/voice/aha-excited.mp3")} />`
  in a `Sequence` at the chosen frame. Read `durationMs` from the manifest to
  place/space them. Grow the bank by editing the JSON and re-running.
